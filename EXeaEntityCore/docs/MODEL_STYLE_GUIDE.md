# EXea Model Style Guide (สไตล์โมเดล 3D ที่ต้องการ + ข้อจำกัดของ EXea)

ที่มา: วิเคราะห์ทีละโมเดลจาก `Entity Model/Only TrainAIModel UseForRef and KnowlegStyle Modeling/` (2026-11-13)
โดยอ่าน glTF → นับ cube, texel density, ความหนาของ cube, จำนวนสีใน texture แล้ว render มุมหน้า/หลัง/ข้าง/3⁄4/บน ดู silhouette

> ⚠️ โฟลเดอร์นั้น **ใช้ศึกษาเท่านั้น** ห้ามนำโมเดล/texture ไปใส่ในเกมหรือ pack (บางตัวเป็น IP ของคนอื่น เช่น Raiden Shogun จาก Genshin Impact) ให้เรียน "วิธีทำ" แล้วออกแบบของเราเอง

## 2. สิ่งที่ทำให้งานอ้างอิงดูดี (สรุปสไตล์)

1. **Texture วาดมือ มีแสงเงาในตัว** — หลักพัน–หมื่นสี: ไล่สี (gradient), AO ตามรอยต่อ, ขอบสว่าง (rim), ลาย (เกล็ด/จุด/ลายชนเผ่า), จุดเรืองแสงสีตัดกัน ไม่ใช่สีพื้นเรียบ
2. **Per-face UV ไม่ใช่ box UV** — แต่ละหน้าวาดต่างกันได้ (หน้าท้องสว่าง หลังเข้ม) และ density เท่ากันทั้งตัว
3. **Texel density เท่ากันทั้งโมเดล** — ส่วนใหญ่ ~16 px ต่อบล็อก (1 px Blockbench = 1 texel) ห้ามมีชิ้นที่ pixel ใหญ่/เล็กกว่าชิ้นอื่น ตัวยักษ์มาก (ปีกกาง > 20 บล็อก) ลดได้เป็น ~10 px/บล็อกทั้งตัว
4. **Cube เยอะ (100–450) และเอียงทุกทิศ** — ไม่ตั้งตรงแกน: ทุกชิ้นหมุนรับรูปทรง ทำให้ดูเป็นธรรมชาติ ไม่เป็นกล่อง
5. **Plane บาง (หนา 0) สำหรับเยื่อปีก ขน แผงหนาม ผม ผ้า** — Raiden 80 แผ่น, Red Dragon 45, King 38
6. **ทรงเรียว (taper)** — คอ/หาง/ขา ใช้ cube ต่อกันที่เล็กลงเรื่อยๆ แทน cube ยาวชิ้นเดียว
7. **Silhouette ชัด เกินจริง** — เขา, ปีก, แผงคอ, อาวุธใหญ่เกินตัว: ดูจากไกลแล้วรู้ทันทีว่าตัวอะไร
8. **ชิ้นส่วนเล็กเพิ่มรายละเอียด** — ฟัน, เล็บ, หนาม, ตา (cube 1–2 px)
9. **สีหลัก 1 + สีเน้น 1** — เช่น ดำ + ส้มลาวา, น้ำเงิน + ขาว, น้ำตาล + กระดูกขาว

## 3. กติกาเพื่อให้ทำงานกับ EXea ได้ (ItemDisplay bones)

| เรื่อง | กติกา | เหตุผล |
|---|---|---|
| **จำนวน bone ที่มี mesh** | ≤ ~30 สำหรับมอนทั่วไป, ≤ ~50 สำหรับบอส | 1 bone = 1 ItemDisplay entity + packet ทุก tick ที่ขยับ — **bone แพง, cube ถูก** (cube ใน bone เดียวกันรวมเป็น item model เดียว) |
| Cube ต่อ bone | ไม่จำกัดในทางปฏิบัติ | ใส่รายละเอียดได้เต็มที่ใน bone เดียว |
| ระยะ mesh จาก pivot | ไม่เกิน 24 px ทุกทิศ (เกินได้ แต่ exporter จะย่อ `mesh_scale`) | item model รับพิกัด −16..32 |
| ชิ้นยาวมาก (ปีก/หาง/ดาบ) | ตัดเป็นหลาย bone ต่อกัน | ได้ทั้งไม่เกินกรอบ และขยับเป็นคลื่นได้ |
| Pivot | วางที่ข้อต่อจริง (ไหล่ ศอก โคนหาง) | การหมุนใน animation หมุนรอบ pivot |
| Bone ที่ไม่มี cube | ใช้เป็นตัวจัดกลุ่มได้ (ไม่สร้าง entity) | เช่น `body`, `head_options` |
| ชื่อ bone | ไม่ซ้ำกัน, ตัวเล็ก_ขีดล่าง (`wing_l_2`) | loader ใช้ชื่อ (lowercase) เป็น key |
| Texture | 1 แผ่นต่อโมเดล, ขนาดใดก็ได้ (128–512), per-face UV | exporter ใช้ texture แรกเท่านั้น |
| Cube หมุน | หมุนได้ทุกแกนทุกมุม | export เป็นรูปแบบ 1.21.11+ (`rotation {x,y,z}`) |
| Plane | ใช้ได้ ต้องใส่ texture ทั้ง 2 หน้า (หรือเฉพาะหน้าที่จะเห็น) | หน้า cube วาดด้านเดียว |
| Inflate | ได้ (exporter ขยาย from/to ให้) | |
| Animation | position/rotation/scale, linear / catmullrom / step | **ห้ามใช้ Molang** (เป็น 0), bezier → เล่นแบบ linear, ห้าม global rotation |
| Effect keyframe (แถว Effects) | **Sound**: ช่อง effect = key เสียง Java (`entity.wither.shoot`) · **Particle**: effect = key particle (`flame`), locator = ชื่อ locator หรือชื่อ bone ที่จะให้เกิด · **Timeline**: script ทีละบรรทัด `hit radius=3.5 damage=20 [cone=120] [bone=hand_r] [knockback=0.5]` (ดาเมจรอบตัว), `sound <key> [volume=] [pitch=] [bone=]`, `particle <key> [count=] [spread=] [speed=] [bone=]`, บรรทัดอื่น = ส่ง `EXeaAnimationEventTriggerEvent` ให้ปลั๊กอินอื่น | Task 12.4 เฟส 3 · ไม่มี effect keyframe = ไม่มีเสียง/อนุภาค/ดาเมจจากท่า (เดิมโค้ดใส่เสียงฟันให้ท่าที่ชื่อมี `slash` เอง — ลบแล้ว) · particle ที่ต้องมีข้อมูลเพิ่ม (dust สี, block) ใช้ไม่ได้ |
| ทิศหน้า | หันหน้าไป **-Z (North)** ใน Blockbench | EXea หมุน 180° ให้ตรงกับทิศที่ม็อบมอง |
| ขนาด | เท้าที่ y=0, สูงได้หลายบล็อก | hitbox มาจาก driver mob ไม่ใช่โมเดล |

สิ่งที่ EXea ยังทำไม่ได้ (ถ้าจำเป็นต้องเพิ่มในโค้ดก่อน): ส่วนเรืองแสงเต็มความสว่าง (ทำได้ด้วย `Display#setBrightness` ต่อ bone เช่นชื่อลงท้าย `_glow` — ยังไม่มีโค้ด), สีโปร่งแสงอาจเรียงลำดับเพี้ยนเมื่อซ้อนกัน

## 4. ขั้นตอนทำโมเดลใหม่ (checklist)

1. **Concept / silhouette ก่อน** — ร่างทรงด้วย cube ใหญ่ 10–20 ชิ้น ดูจากหน้า/ข้าง/บน ให้จำได้จากเงาดำ
2. **วาง bone ตามข้อต่อ** — นับ bone ที่มี mesh ให้อยู่ใน budget (ข้อ 3) แยก bone สำหรับส่วนที่ต้องขยับ (หัว, กราม, แขนแต่ละท่อน, ปีก 2–3 ท่อน, หาง 3–6 ท่อน)
3. **เติมรายละเอียด** — taper, plane สำหรับขน/ปีก, ฟัน/เล็บ/หนาม, หมุน cube ให้รับรูปทรง เป้าหมาย 120–300 cube สำหรับบอส
4. **UV per-face, density เท่ากัน** — ตั้ง texture 256² (บอสใหญ่ 512²) ให้ 1 px = 1 texel
5. **วาด texture** — สีพื้น → เงา/AO ที่รอยต่อและใต้ท้อง → highlight ด้านบน/ขอบ → ลาย → สีเน้น/จุดเรืองแสง (เป้าหมาย: หลักพันสีขึ้นไป ไม่ใช่สีเรียบ)
6. **Animation** — idle (หายใจ + ชิ้นลอยขยับเบาๆ), move, attack 2–3 ท่า, death (hold) ใช้ catmullrom ให้ลื่น ระวังมุมเกิน 180° ต่อ keyframe
7. **Export** — บันทึก `.bbmodel` → `node EXeaEntityCore/tools/exea_exporter.js "<file>.bbmodel" <id>` → อ่าน `[WARN]` / `[SCALE]` → build jar → `/exea spawn <id>`

## 5. บทเรียนจากการสร้าง Vaelith (2026-11-13) — อ่านก่อนสร้างตัวใหม่

### 5.1 ขั้นตอนที่ได้ผล (ทำตามลำดับนี้)
1. **Generator ก่อน, Blockbench ทีหลัง** — เขียน geometry + texture + ท่าพื้นฐานเป็นสคริปต์ (`EXeaEntityCore/tools/models/<id>_gen.mjs`, ดู `vaelith_gen.mjs` เป็นแม่แบบ) แก้ตัวเลขแล้วสร้างใหม่ได้ทันที ไม่ต้องลากทีละ cube
2. **เปิดใน Blockbench ผ่าน MCP** — `node tools/bbreload.mjs "<file>.bbmodel" "<ชื่อโปรเจกต์>"` (ปิดแท็บเดิม เปิดใหม่)
3. **ดูผลจากหลายมุมเอง** — `node tools/bbshots.mjs <prefix> [anim] [time]` (offscreen view ไม่ขยับกล้องผู้ใช้), หน้าใกล้ๆ `node tools/bbface.mjs <prefix> x y z dist`
4. **พอ geometry นิ่ง → ทำ IK ใน Blockbench → ทำท่า → bake** (`set_ik_controller` แล้ว `node tools/bbbake.mjs`) → **save จาก Blockbench** — ตั้งแต่ตรงนี้ไฟล์ `.bbmodel` คือต้นฉบับ (ห้ามรัน generator ทับ ไม่งั้น IK/ท่าที่แก้ใน Blockbench หาย)
5. **วัดค่าจริงใน Blockbench เมื่อสงสัย** (`risky_eval` อ่าน `group.mesh.position/rotation` ที่เวลาหนึ่ง) — อย่าเดาจากภาพ
6. Export: `node EXeaEntityCore/tools/exea_exporter.js "<file>.bbmodel" <id>` + `<id>_meta.json` ข้าง .bbmodel → `gradlew jar` (เซิร์ฟปิด) → `/exea spawn <id>`

### 5.2 ข้อเท็จจริงที่วัดแล้ว (อย่าเสียเวลาหาใหม่)
- **Keyframe ใน .bbmodel ไม่ต้องกลับเครื่องหมาย** — Blockbench 5.2 บวกค่าตรงๆ ทุก format, Euler `ZYX` (ดู `Format.euler_order`)
- แกน (หน้าโมเดลหัน -Z): rotation **X บวก** = ปลายที่ชี้ -Z เงยขึ้น / ส่วนบนเอนไปข้างหลัง → **เอนไปข้างหน้า / ก้ม = X ลบ**; rotation **Y บวก** = หันจาก -Z ไปทาง -X; rotation **Z บวก** = แขนฝั่ง +X ยกขึ้น; position เป็น px ในพิกัดของ parent
- ฝั่ง `_l` อยู่ +X (ตาม convention ของ Minecraft model)
- Format **Modded Entity บังคับ box UV** → ใช้ **Generic Model (`free`)** ถ้าจะวาด per-face
- Element rotation หลายแกน/เกิน 45° ใช้ได้ (1.21.11+) exporter เขียนรูปแบบ `{x,y,z}` ให้
- Density 2 texel/px (32 ต่อบล็อก) อ่านรายละเอียดหน้า/ผมได้ดีสำหรับตัวละครเล็ก; texture 512×256 พอสำหรับ ~180 cube

### 5.3 สูตรหัว/หน้าแบบ anime (วัดจากข้อมูล pixel ของงานอ้างอิง ไม่ใช่ดูจากภาพ)
- หัว **8 px (16 texel)** ≈ กว้างเท่าไหล่ + **hair shell 9 px (18 texel)** ครอบ (แบบ overlay ของ skin) ด้านล่างของ shell ไม่ใส่ texture
- หน้า = หน้า north ของ skull วาดเหมือน skin 8×8 ขยาย 2 เท่า: แถว 0–2 ผม, ข้างๆ ผม 1 คอลัมน์, **ตาอยู่ต่ำ แถว 7–10 (จาก 16)**: แถวขนตาเข้ม → ม่านตาเข้ม → ม่านตากลาง → ม่านตาสว่าง, ตาขาวอยู่ด้านนอก, highlight 1 texel ที่มุมบนของม่านตา, แก้มชมพู 2 texel, ปาก 1 texel หรือไม่ใส่, ไม่มีจมูก
- หน้า north ของ hair shell = mask หน้าม้า: บน ~7 แถวทึบ แล้วแต่ละคอลัมน์ยาวไม่เท่ากัน, เส้นกลางยาวลงมาระหว่างตา, ม่านข้างยาวถึงคาง (ดู `FACE` / `BANG_LEN` ใน `vaelith_gen.mjs`)
- ผมยาวด้านหลัง = ก้อนหนาหลายชั้น (ไม่ใช่ plane แผ่นเดียว) + ปลายฉีก + แถบ highlight ("angel ring") ช่วงบน
- สีผมต้องต่างจากสีผิวชัดๆ (รอบแรกผมขาวกับผิวขาวกลืนกัน)

### 5.3b สัดส่วนตัว/ขา (วัดจากข้อมูล cube ของงานอ้างอิง, หน่วย = หัว 8 px)
- หัว 1 · ลำตัว (คอ→สะโพก) ~0.9 กว้างแค่ ~0.75 หัว · **ขา ~2 หัว** (ต้นขา ~1, หน้าแข้ง+รองเท้า ~1) → รวม ~4 หัว
- แขน/ขาเรียว: ต้นขา ~3 px, หน้าแข้ง ~2.5 px, แขน ~1.5 px — ลำตัวแคบกว่าหัว (สไตล์ chibi-elegant)
- กระโปรง = แผ่น plane หลายแผ่นรอบสะโพก เอียงออก เปิดด้านหน้าให้เห็นขา (ไม่ใช่ท่อทรงกระบอก)
- Vaelith: ลำตัว 25→33 px, ขา 22.4→0 px (thigh/shin/boot), แผ่นกระโปรงหน้า 2 แผ่นแยกกัน

### 5.3c Rig / ท่า
- **มี bone `hips` เป็นรากของตัวละคร** (body → hips → torso/legs/skirt) — ท่าตาย "ล้มลงพื้น" = หมุน hips ~82° + เลื่อนลงถึงพื้น ชิ้นลอย (มือยักษ์/อาวุธ) เป็นลูกของ body จึงร่วงแยกได้
- IK: เขียนเป็นสคริปต์ (`tools/models/vaelith_rig.mjs`) รันหลัง generator ทุกครั้ง → IK + pole + key + bake + save อัตโนมัติ ไม่ต้องทำมือซ้ำ
- **ใส่ pole target ทุก IK chain** (null หลัง/นอกศอก) ไม่งั้นศอกพับผิดทิศ
- IK เฉพาะส่วนที่มีเป้าหมายจริง (มือ) · ขาที่ลอยไม่แตะพื้นใช้ FK — IK ที่ไม่มี key ใน animation ไหนจะทำให้ Blockbench แสดงไม่ตรงกับในเกม (bake ทำเฉพาะ animation ที่มี key ของ null)
- ท่าหมุนอาวุธหน้าตัว: เลื่อนวงหมุนไปหน้า (z −26) และยกมือยักษ์ออก/ถอยหลัง/ชี้นิ้วขึ้น — เช็คจากมุมข้าง (side) ว่าไม่ทะลุกัน

### 5.4 สิ่งที่พลาดแล้วต้องแก้ (เช็คก่อน)
- **Texture แบบ link (`relative_path`) ใน .bbmodel** → Blockbench อ่านไฟล์จาก cache เก่าหลัง generator เขียนใหม่ → UV ไม่ตรง ลายเพี้ยน และ save จาก Blockbench จะฝังภาพเก่ากลับลงไฟล์ → generator ต้อง **ฝัง texture อย่างเดียว** (ไม่มี `relative_path`)
- ไม่มีขา/ลำตัวใหญ่เกิน → ดูไม่สมส่วน: ใช้สัดส่วน §5.3b
- ท่าตายแบบเอนตัวเฉยๆ (เหมือนท่าเต้น) ไม่ผ่าน → ต้องลงไปนอนกับพื้นจริง (วัด y ของส่วนที่ต่ำสุด ≈ 0)
- กลับเครื่องหมาย keyframe ตามความเชื่อแบบ Bedrock → ท่าออกทิศตรงข้าม (แขนกางออกแทนหุบเข้า) — **วัดก่อนเสมอ**
- Gauntlet/ชิ้นยาวเป็นกล่องยาวทรงท่อน → ดูไม่มีชีวิต: สั้นลง + ปลายบาน + เอียงด้วย rest rotation + นิ้วกางคนละองศา
- รอยแตกบน texture แบบสุ่มจุด → ดูเป็นสิว: ใช้เส้น random-walk 1–2 เส้นต่อหน้า
- มุมกล้องจากด้านบนทำให้ชิ้นที่อยู่ไกลดูสูงกว่า → ตรวจท่าด้วยมุมหน้าตรงก่อนสรุปว่าผิด
- Exporter รุ่นเก่าเขียน pack แยกต่อโมเดล → zip ทับกัน (แก้แล้ว: รวมใน `EXeaEntityCore/pack`)
- IK: ต้องมี bone ปลายสายว่างๆ (`hand_l`) เป็น end effector ถึงจะได้ข้อต่อ 2 ข้อ (ไหล่+ศอก); bone ว่างไม่เสีย entity
- Blockbench MCP ใช้ port 3010 (3000 ชนกับ web console); เรียกผ่าน `tools/bbmcp.mjs` ได้แม้ session ยังไม่โหลด MCP; บน Windows ใช้ PowerShell ห้าม `cmd`

### 5.6 Item model — บทเรียนจาก Thing Sword / Prim Metal / Training Key / Engrave Solvent (2026-11-13)
- Generator: `tools/resourcepack/items/misc_items_gen.mjs` (ทั้ง 4 ชิ้นในไฟล์เดียว, `node … <name>` สร้างชิ้นเดียว) — ชิ้นส่วนเขียนเป็น `box()` / `diamond()` ในกรอบตั้งตรง แล้ว `tilt` ทั้งชิ้น; painter ต่อหน้าได้ `ctx.pt(x,y)` = พิกัดโลกของ texel (ใช้ตัดระดับน้ำในขวดตาม y จริง)
- **GUI มองจาก +Z (หน้า south)** → ดาบ tilt −45° = ปลายขวาบนเหมือน vanilla, กุญแจ tilt +45° = ห่วงซ้ายบน
- **กล่องซ้อนกันห้ามโปร่งใส**: หน้าของกล่องที่ซ้อนอยู่ข้างในจะโผล่ให้เห็นผ่าน texel โปร่ง → แก้วขวด "ระบายให้ดูใส" แบบทึบ (สีฟ้าเข้ม + เส้นสะท้อนแสงขาว 1–2 คอลัมน์ด้านซ้าย) ไม่ใช้ alpha
- **ขอบ (rim) ที่วาดตามขอบหน้า ใช้กับกล่องที่ซ่อนอยู่ไม่ได้**: กล่องเสริมมุมขวด (ทำให้กลม) โผล่แค่ขอบหน้า → ถ้ามี rim ขอบนั้นกลายเป็นแท่งสีเข้มกลางมุม → ให้ painter รับ option `rim=false` สำหรับกล่องเติม
- ขวดกลม: แกน 6×6.5×6 + กล่องนูนแกน x 8 กว้าง + แกน z 8 กว้าง + กล่องมุม 7×7 → ดูเป็นแปดเหลี่ยมโค้ง ไม่ใช่ลูกบาศก์; ป้ายกระดาษวาดบนหน้า north/south ของกล่องนูนแกน z (ไม่ต้องเพิ่ม element)
- แท่งโลหะ (ingot) 2 ชั้นดูเป็นแผ่นซ้อน → **3 ชั้นหดทีละ ~0.6 px** อ่านเป็นแท่งหล่อเรียว; ลายตอกบนหน้า up: ร่องมืดฝั่งบนซ้าย + ขอบนูนสว่างฝั่งล่างขวา + ไส้แร่ teal ตรงกลาง (สีจาก ramp ตรงๆ ไม่ใส่ noise จะคมกว่า)
- ใบดาบ: noise ต่ำ (0.14) + คม 1 texel สว่างต่อเนื่อง + ร่องเลือด (fuller) 2 คอลัมน์ มืด/สว่าง ค่าคงที่ — noise สูงทำให้ร่อง/คมดูเลอะ; เส้นแร่ teal random-walk 9 texel ตัด palette โลหะเย็นได้ดี
- ใช้ ramp 6–9 สี + Bayer dither 4×4 (`shade()`) แทน gradient ต่อเนื่อง → ได้ "painted pixel" ไม่ใช่ flat และไม่เบลอ; ตัดกันด้วยวัสดุต่าง hue (หนังน้ำตาลกับโลหะฟ้าเทา, กุญแจทองเหลืองกับคริสตัล teal, น้ำยาเขียวกรดกับแก้วฟ้า)

### 5.5 บทเรียนจาก Void Overseer (แก้ท่า + IK, 2026-11-13)
- **กฎสูงสุด: แก้ไฟล์ล่าสุดเสมอ** — ผู้ใช้แก้โมเดล/ท่าเองระหว่างคำขอ → อ่าน `.bbmodel` จาก disk ใหม่ทุกครั้ง ห้ามสร้างใหม่จาก generator/rig script/export เก่า/git · rig script ที่ล้าง key ของ bone ที่ตัวเองเป็นเจ้าของจะทับท่าที่ผู้ใช้แก้เอง → ถ้าไฟล์เปลี่ยนหลังรันครั้งล่าสุด ให้ backup + เทียบท่าก่อน แล้วนำการแก้ของผู้ใช้เข้าไปในสคริปต์ (หรือถามก่อน)
- **โมเดลที่ไม่มี generator: `.bbmodel` คือต้นฉบับ** → rig script (`tools/models/void_overseer_rig.mjs`) ทำทุกอย่างบนไฟล์นั้นแบบรันซ้ำได้: แยก bone (`forearm_*`, `hips`) ถ้ายังไม่มี, ล้าง key ของ bone ที่สคริปต์ "เป็นเจ้าของ" (`OWNED`) ทุกท่าก่อนใส่ใหม่, IK + pole, bake, save · ทดสอบด้วย `--no-save` ก่อน แล้วรันเต็ม (reload จากไฟล์เดิม) เพื่อพิสูจน์ว่าสร้างซ้ำได้
- **แขนท่อนเดียว (ไม่มีศอก) ทำ IK ไม่ได้** → แยกแขนท่อนล่างเป็น bone ใหม่ที่ pivot ศอก แล้ว chain = `arm_*` → `forearm_*` → `hand_*` (pivot ของ hand = ข้อมือ = end effector, ไม่ต้องเพิ่ม bone ว่าง เพราะ IK ไม่หมุนตัว target; การหมุนของมือ/นิ้วยังเป็น FK)
- **อย่าเดาตำแหน่งข้อมือตอนพักจาก origin ของ bone** — rest rotation ของไหล่/แขน (z −10/−5) ดึงข้อมือจาก x 13 เข้ามาที่ x 8.1 → เป้า IK ที่คิดจาก origin เข้าในไป 5 px ชนซี่โครง/แกนกลาง/มืออีกข้าง · วิธีที่ใช้: เขียน key IK เป็น **ตำแหน่งข้อมือแบบ absolute** (torso space) แล้วให้สคริปต์ลบด้วย `null.position` (null ที่ `set_ik_controller` สร้างอยู่ที่ข้อมือจริง)
- **ระยะเอื้อม** = ต้นแขน + แขนล่าง (ที่นี่ 9.5 + 6.5 = 16 จากข้อไหล่ (±12.2, 34.4, 0)) — เป้าที่ไกลกว่านั้นแขนจะเหยียดตรงเอง; แขนล่างหนา 7 px → เวลาผ่านหน้าลำตัวต้องให้ z ≤ −10
- **ตรวจการทะลุด้วยตัวเลข ไม่ใช่ภาพ**: สุ่มทุก 0.05 วิ (ปิด IK ให้เหมือน EXea ที่เล่นแค่ FK), ทดสอบ OBB ด้วย SAT ระหว่างกลุ่ม (มือ/แขนล่าง/ต้นแขน/ไหล่ ซ้าย-ขวา, ลำตัว+หัว+core, orbiters) ข้ามคู่ที่ต่อกันโดยตรง, รายงานที่ลึก > 0.6 px + จุดต่ำสุดของทุก cube (ต้อง ≥ 0) · รอบแรกเจอ ~300 คู่ → 0 ทุกท่า
- **ทางเดินของมือระหว่าง key ก็ชนได้** (catmullrom ลากตรงผ่านไหล่/หัว) → ใส่ key กลางทางให้มืออ้อมไปด้านหน้า/ด้านนอก
- **ชิ้นลอยที่วนรอบเอว (orbiters) ขวางทางแขนทุกท่าโจมตี** → ตอนโจมตียก orbiters ขึ้นเป็นวงรัศมีเหนือไหล่ (pos y +12) และอย่าย่อ scale จนวงหดเข้ามาชนแขน
- **ท่าตาย**: เพิ่ม `hips` (body → hips → torso) แล้วหมุน hips +90 (นอนหงาย) + ลง −17; key ช่วงล้มเป็น `linear` (catmullrom พุ่งเลยพื้นตอนกระแทก −3.7 px) · orbiters (ลูกของ body ที่อยู่นิ่ง) ร่วงเองลงพื้น: ยกกำลัง scale รอบ pivot ต้องคิดจุดต่ำสุดใหม่ (25 → 24.25 ที่ scale 1.25) และหมุนให้จอดไม่ทับแขน/หัว
- **pole อยู่ใน torso space** → ตอนนอนหงาย pole ที่อยู่ข้างหลัง (z +9) กลายเป็นใต้พื้น ศอกพับลงดิน → key ตำแหน่ง pole ในท่าตายให้มาอยู่ระดับพื้น/ด้านข้าง (bake อ่านตำแหน่ง pole ทุกเฟรม)
- **Blockbench ใช้ร่วมกันหลาย session**: ทุก MCP call ทำงานกับ project ที่ active → ตั้ง `BBMCP_PROJECT=<ชื่อโปรเจกต์>`; `bbmcp.mjs` มี `inProject(code)` ที่เลือกโปรเจกต์ → รัน → คืนโปรเจกต์เดิม (eval หนึ่งครั้งไม่ถูกแทรก) · `bbshots` อาจได้ภาพไม่ครบ ("Unknown view") หรือภาพจากเฟรมที่ถูกเปลี่ยนเวลา → รันซ้ำเฉพาะภาพที่ขาด และเชื่อตัวเลขที่วัดมากกว่าภาพ
- `risky_eval` ห้ามมี `//` comment หรือ `console.` ในโค้ด

## 6. ไอเดียที่เหมาะกับ EXea เป็นพิเศษ

- **บอสแบบ "แกนกลาง + ชิ้นลอย"** (แนวเดียวกับ Raiden / Void Overseer orbiters): ชิ้นลอยไม่ต้องมีข้อต่อ หมุนวน/ลอยขึ้นลงได้อิสระ ใช้ bone น้อยแต่ดูอลังการ
- **มังกร/สัตว์ปีก**: ปีกแบ่ง 2–3 bone ต่อข้าง (โคน, กลาง, ปลาย) + เยื่อปีกเป็น plane, หาง 4–6 bone เล่นคลื่นด้วย catmullrom โดยเลื่อนเวลา (offset) ทีละท่อน
- **สัตว์สี่ขาหนัก** (แนว King): ขาท่อนละ bone 2 ท่อน, หัว+กรามแยก, แผงขนเป็น plane ใน bone ของคอ (ไม่ต้องแยก bone)
